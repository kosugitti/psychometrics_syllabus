\chapter{ベイズを実践する}
\label{ch29_bayesianModeling}

ここまで，ベイズの定理からはじまって，事後分布による推定，そしてベイズ的な判断の仕方までを見てきました。前講ではJASPを使って，実際に手を動かしてベイズ分析を体験してもらいました。

しかし，ひとつ大きな疑問が残っているはずです。事後分布は，事前分布と尤度の積を積分して求めるのでした。その積分がとても難しいから，ベイズ法は長らく使えなかったのだ，という話もしました。それなのに，JASPのボタンを押すと数秒で答えが返ってくるのはなぜでしょうか。裏側で何が動いているのでしょうか。

この答えにつながる技術的なブレイクスルー，そしてそれを使った実践的なベイズ分析の方法について，見ていきましょう。そしてこのことを知ると，今まで「データを見て，それにあった分析法を探す」という受動的なデータ解析の姿勢から，「データの生成メカニズムを自分で考え，それをモデル化する」という能動的でクリエイティブなデータ解析へと，私たちの姿勢を変えることができるのです。

\section{ベイズを実践する方法}
\subsection{ベイズ法が普及しなかった理由}

ベイズ法は頻度主義的な方法と比べて，利点も少なくありませんが，21世紀になるまでそこまで広く用いられることはありませんでした。実際，2010年ごろからベイズ法が心理学領域でも広まってきたのですが，18世紀にトーマス・ベイズが提唱して以来，200年以上もかかっているのです。なぜでしょうか。その理由を3つほど挙げてみましょう。

第一の理由は，頻度主義者のフィッシャーがベイズ法を批判したことにあります。フィッシャーは厳格な科学的手続としての統計学の実践的利用を考えた人で，科学的な態度として事前分布の存在が許せなかったようです。データと向き合う前に何らかの思い込みを持つことは，科学的態度として適切でないと考えたようですし，「事前に何も想定しないこと」と「無情報事前分布をもつこと」は本質的に違うと考えていたようです。彼の言葉として「逆確率の理論はある誤謬の上に立脚するものであって、完全に葬り去らなければならない」，というのが知られています。いずれにせよ，統計学が花開かんとする時期に，その大御所に嫌われていると，どうしても後続が育たないという事情がありました。

第二の理由は，ベイズ統計学の実践的事例が，軍事関係にあったことにあります。暗号解読などに強力なベイズ的手法が用いられたことは知られていますが，軍事関係の研究は秘密主義的であり，その内容が広く知られることはありませんでした。これにより，学術的なコミュニティでのベイズ法の普及が妨げられたといわれています。これらの話は，\textcite{mcgrayne2011theory}に読み物として詳しく書かれていますので，興味がある人はぜひご一読ください。

さて。とはいえ，それらはまだ副次的な理由にすぎません。第三の理由はもっと本質的なものです。それは，ベイズの理論は正しくても，計算が難しすぎるという問題です。ベイズの定理が示すように，ベイジアンは，事後分布を求めるために，事前分布と尤度関数を掛け合わせたものを周辺尤度で割る，という計算を行います。しかし，この分母にあたる「周辺尤度」を計算で求めるのがとても難しいのです。事前分布と尤度の積を，事前分布の全領域で積分しなければならないのですが，この積分が解析的に(計算機で)解ける場合は限られています。特に多次元の場合は，この積分を解析的に解くことはほぼ不可能です。

これまで，ベイズの研究者はこの問題を解決するために様々な工夫をしてきました。ひとつは，事後分布の形が計算できるわかりやすいものにすること，特に事前分布と事後分布が同じ形の分布になるような，特殊なケースを探すことです。このようなケースを\keytermsub{共役事前分布}{きょうやくじぜんぶんぷ}{conjugate prior}{事前分布}{じぜんぶんぷ}といいます。たとえば，二項分布の成功確率の事後分布を求める場合に，ベータ分布を事前分布に選ぶと，事後分布もベータ分布になる，ということがわかっています。この方法は解析的に解ける場合に限られますが，計算が簡単になるため，古くから用いられてきました。

あるいは，グリッドサーチという方法です。これは計算したい範囲を細かく区切り，その各点で事前分布と尤度を計算し，それらを掛け合わせて正規化することで，事後分布を近似的に求める方法です。各領域での計算結果から，より事後分布の確率密度が高いところを探していくという方法で，計算できなくはないのですが，かなりの計算量を必要とするものでした。これらの方法では，あまり実践的な利用には向いていません。つまり，ベイズの定理は理論的には正しいけれど，絵に描いた餅だという状況だったのです。

\subsection{MCMC法の登場}

ところが，近年になって技術的なブレイクスルーが生じます。\keyterm{マルコフ連鎖モンテカルロ法}{まるこふれんさもんてかるろほう}{Markov chain Monte Carlo}と呼ばれる手法です。これを用いることで，事後分布を近似的に求めることが可能になったのです。この手法は略してMCMC法と呼ばれますが，前のMCと後ろのMCは違うもの，二つのMCの合体技です。

前のMC，すなわちマルコフ連鎖とは，「機械の中になんだか安定的な確率空間を作ること」を意味します。ベイズ法が実践的でなかったのは，事後分布を計算するのが難しいことだったのですが，マルコフ連鎖を使うことで事後分布の形状に近い確率空間を作ることができるのです。

後ろのMCはモンテカルロ法。モンテカルロというのはモナコの地名です\footnote{F1グランプリが好きな人は，モナコのコースがモンテカルロだというのをご存知かと思います。街中を走る，すごいシケインのある難しいコースですが，美しい街並みで富裕層やセレブリティの居住地としても知られています。}。モナコにはカジノがありますから，ギャンブルの代名詞のようにつかわれているのですが，モンテカルロ法は「乱数を発生させる方法」だと思ってください。\keyterm{乱数}{らんすう}{random number}とは，規則性のない数字のことです。人間が「規則性のない数字を適当に羅列して」と指示されると，1,3,6,5,8,2,0,3,5,9,2,....のように適当な数字を上げることはできると思いますが，これを長い目で見てみると5,3,8などの数字が他よりも多く発生すると言われています。つまり，人間が作る乱数は完全にランダムではないのです。そこでコンピュータにランダムな数字を出させるのですが，コンピュータの中身はプログラミングで規則正しく動いていますから，規則正しく規則性のない数字を出せ，というのは語義矛盾のように思います。これを工夫して，とある数字を生み出す関数を生み出す関数を作り，その関数を反復的に活用していくことであたかも規則性がないような数字を出す方法，というのが考えられてきました。コンピュータの出すこのような乱数は\keyterm{擬似乱数}{ぎじらんすう}{pseudorandom number}と呼ばれ，スタート地点さえ同じであれば同じ数列が出てくる(規則にしたがっている)ため，完全な乱数ではありません。が，その数列自体は人間よりもはるかに不規則で均一な分布を作ることができます。これができれば，少し加工してたとえば正規分布に従う乱数を作る，ということも可能です。みなさんがゲームで「ガチャを引く」とか，「ランダムにアイテムをもらう」とかいうときに，計算機は内部でこの擬似乱数を使っているわけです。

MCMC法はこのマルコフ連鎖＋モンテカルロ法です。つまり「事後分布っぽい空間を作ること」＋「乱数を発生させる」ですから，「事後分布から乱数を発生させる」ことができるのです。事後分布の関数の形はわかりませんが，事後分布から乱数を発生させることができる。これがMCMC法の本質です。「乱数なんか作ってどうするんだ」と思われるかもしれませんが，ある分布に従う乱数というのは，その分布の本質を反映するとても面白いものなのです。

	\caption{正規分布の乱数を大量に発生させたもの。左上は100個，右上は1000個，左下は10,000個，右下は100,000個の乱数を生成してヒストグラムにしたもの}
	\label{fig:29_01}
\end{figure}

図\ref{fig:29_01}には，正規分布に従う乱数を生成させた図を示してあります。左上は100個の乱数をつくっていますが，そのヒストグラムはガタガタであんまり正規分布っぽくはありませんね。右上は1000個です。これぐらいになると，どうやら正規分布っぽい感じ，つまり中央が高くて両裾にむけた緩やかに減衰する感じが見て取れます。左下は10,000個です。ここまでくると理論的な正規分布のカーブの影が見えてきますね。右下は100,000個ですが，ここまでくるとほぼ理論的な正規分布のカーブを描いているかのようです。

このように，乱数を大量に発生させ，そのヒストグラムを描くと，稜線\footnote{りょうせん。すなわち山の尾根のことで空と山の境目の線のことです。}が，その分布の形を反映するのです。事後分布の関数の形は分からなくとも，乱数のヒストグラムで分布の形状を近似的に知ることができます。

乱数のメリットはそれだけではありません。セクション\ref{sec:10_02}(Pp.\pageref{sec:10_02})で見たように，確率分布の期待値を求める計算は，次のようになります。

\[ E(X) = \sum x_i \times p_i \]

これは離散分布の場合ですが，要するに実現値とその確率をかけて足し合わせることになります。連続分布の場合はここでも積分が出てきます。面倒ですね！
しかし，乱数を使うとこの計算はとても簡単になります。というのも，乱数の実現値が大量にできているのですから，それを集計して，平均の計算をするだけで期待値になるのです。確率分布の分散の計算も面倒ですが，実現値が大量にあるわけですから，そのまま分散の計算をすれば良いのです。

もっといいことに，特定の領域の確率を計算したいとしましょう。たとえば標準正規分布で，-1から+1までの範囲の面積(確率)を求めるには，次の計算をする必要があります。

\[\int_{-1}^{+1} \frac{1}{\sqrt{2\pi \sigma^2}} \exp \left(-\frac{(x-\mu)^2}{2\sigma^2}\right) dx \]

また積分です。当然です，確率は面積なんですから。でも面倒ですね！

しかし，乱数で実現値が大量にあるわけですから，得られた乱数のうち-1から+1までの範囲に入っているものの割合を計算すれば，その範囲の確率を計算したことになります。このように，あくまで近似的ではありますが，乱数を使うことで積分の計算が集計の方法に変わるのです。

そして私たちにはRのような，データの集計に特化した言語があります。事後分布の乱数が大量にあれば，結果をRで集計させるだけで複雑な確率分布の計算に頭を悩ませる必要がないのです！素敵！

乱数によるアプローチの利点は他にも，ある変数に関する周辺分布を求める場合にも有効です。たとえば正規分布は$\mu$と$\sigma$の二変数をもつ分布ですが，$\mu$に関する周辺分布が欲しい場合($\mu$だけの分布が欲しい場合)は，乱数の中から$\mu$変数についてのみ集計すれば良いのです。図\ref{fig:29_02}に示すように，乱数が大量にあれば，特定の変数について集計するだけで周辺分布を求めることができます。

\begin{figure}[ht]
	\centering
	\includegraphics[keepaspectratio,width=0.65\linewidth]{figures/29_bayesian_modeling/marginal.png}
	\caption{周辺分布も当該変数の集計で求められる}
	\label{fig:29_02}
\end{figure}

MCMC法による乱数で結果を確認するのは，近似にすぎないといえばそうなのですが，乱数の数を増やせば増やすほど精度は上げることができますし，最近のコンピュータの能力を使えば10万，100万の乱数を作るのも簡単ですから，実用上は十分な精度が得られます。ベイズ法が実践的な手法として普及したのは，このMCMC法の登場によるところが大きいのです。

\subsection{確率的プログラミング言語}

このMCMC法を用いたベイズ推定を実践するために，\keyterm{確率的プログラミング言語}{かくりつてきぷろぐらみんぐげんご}{probabilistic programming language}というものが開発されてきました。有名なものに\keyterm{JAGS}{JAGS}{JAGS}，\keyterm{BUGS}{BUGS}{BUGS}，\keyterm{Stan}{Stan}{Stan}などがあります。これらはR言語のように，プログラミング言語の一種で，データと尤度，事前分布の関係を記述してやると，MCMC法を用いて事後分布から乱数を生成してくれる，というものです。

\begin{figure}[ht]
	\centering
	\includegraphics[keepaspectratio,width=0.65\linewidth]{figures/29_bayesian_modeling/HowToUseStan.png}
	\caption{Stan言語とR言語の連携}
	\label{fig:29_03}
\end{figure}

図\ref{fig:29_03}にStan言語とR言語の連携の例を示します。Stan言語でモデルを記述し，R言語からStanを呼び出してデータを渡し，MCMC法で乱数を生成してもらい，R言語で集計する，という流れです。Stan言語自体はC++\footnote{日本語ではシープラスプラス，と読まれることの多い，コンピュータ言語です。C言語というのがあったのですが，それの一歩次に行くという意味の表記です。ちなみに\verb|++|というのはC言語の表記で1を足すという操作を指します。Rで\verb|a <- a + 1|と書くことでオブジェクトaを1つ増やすことができますが，C言語ではこれを\verb|a++|と書くだけでいいのです。}で書かれているため高速に動作しますし，R言語から簡単に呼び出せるため，Rユーザーにはとても便利なツールです。

これを使うと，今まで絵に描いた餅だったベイズ法が簡単に使えるようになります。だって，データと確率分布の関係を書くだけでいいんですから。そしてMCMC法をつかったベイズ推定はとても強力ですから，非常に複雑なモデルであっても答えを捻り出してくれます。何十ものパラメータがあっても大丈夫です。そうなってくると，ベイズ法を使わない手はありません。「わからないものを確率で表現する」という思考方法さえ身につければ，どんなモデルであっても答えが出せますから，心理学のように確率的で不確実なものを扱う領域にはもってこいなのです。

\section{brmsによる実用的モデリング}

第\ref{ch28_bayesian_with_JASP}講では，JASPというGUIソフトウェアを使ってベイズ的な分析を体験しました。マウスで操作できるのは手軽ですが，一つだけ制約があります。それは，\textbf{メニューに用意されている分析しかできない}ということです。前節で見たように，確率的プログラミング言語を使えばデータの生成メカニズムを自分で書き下すことができるのですから，メニューから選ぶという発想そのものが窮屈になってきます。

とはいえ，Stan言語をゼロから書くのは，初学者には難しく感じるでしょう。そこで，まずはパッケージの力を借りましょう。ここで紹介するのはRの\keytermRL{brms}{brms}パッケージ\parencite{brmsCite1}です。brmsはBayesian Regression Models using Stanの略で，その名のとおりStanを使った回帰モデルを，\textbf{Rの式記法のまま}書けるようにしてくれるものです。私たちが\verb|lm()|や\verb|glm()|で使ってきた\verb|y ~ x|という書き方が，そのまま使えるのです。

\begin{caution}{brmsを使う前に，インストールを済ませておくこと}{brms-install}
brmsはRのパッケージですが，計算そのものはStanが行います。そのため\verb|install.packages("brms")|とするだけでは動きません。お使いのパソコンにC++のコンパイラと，Stanの本体であるcmdstanを入れておく必要があります。この準備はOSによって手順が異なり，つまずきやすいところでもありますので，実践したい人はこの章末にある補遺(セクション\ref{prepare_stan},Pp.\pageref{prepare_stan})を参照して先に済ませておいてください。
\end{caution}


\subsection{lm()をbrm()に書き換える}

第\ref{ch09_Regression_onR}講と第\ref{b24_linear_model}講で使った，野球選手のデータをもう一度使いましょう。打者の身長から体重を予測する回帰分析です。第\ref{b24_linear_model}講では，これを最小二乗法と最尤法という二つの方法で推定したのでした。今度はこれを，三つめの推定法であるベイズ推定でやってみます。

\begin{lstlisting}[language=c++,label={code:29_01},caption={データの準備とパッケージの読み込み}]
rm(list=ls())
library(tidyverse)
library(brms)
dat <- read_csv("baseballDecade.csv", na="NA",
        locale=locale(encoding="utf8")) %>%
        filter(Year=="2020年度")
batter <- dat %>%
  dplyr::filter(position != "投手") %>%
  dplyr::select(height, weight, HR, AtBats)
\end{lstlisting}

ここまでは第\ref{ch09_Regression_onR}講とまったく同じです。ここから先が本題で，推定のコードを見比べてみてください。

\begin{lstlisting}[language=c++,label={code:29_02},caption={最尤推定とベイズ推定を並べてみる}]
# 第24講でやった最尤推定
result.LM <- lm(weight ~ height, data = batter)
# 今回のベイズ推定
result.BRM <- brm(weight ~ height, data = batter, seed = 12345)
\end{lstlisting}

いかがでしょうか。\verb|lm|が\verb|brm|になっただけです\footnote{\texttt{seed}引数は乱数の出発点を指定するものです。MCMC法は乱数を使いますから，指定しないと実行するたびに結果の細かい数字が変わります。同じ結果を再現できるようにしておくのは，研究の作法として大事なことです。}。第一引数のモデル式も，データの指定も，何も変わっていません。これだけで，裏ではStanのコードが自動生成され，コンパイルされ，MCMC法が走り，事後分布からの乱数が返ってきます。

ただ，その後ろの数字が，最尤推定の場合とちょいと違います。
最尤推定の時は\verb|Std. Error|, \verb|t value| ,\verb+Pr(>|t|)+と並んでいます。それぞれ標準誤差，$t$値，$p$値です。点推定がどれほどの幅を持ってブレる可能性があるのか。推定値が0であるという帰無仮説から考えると，どれだけ外れてるのか。それは統計的に有意か。ということが書かれていたのでしたね。

これに対してベイズ推定の場合は\verb|Est.Error|,\verb|l-95% CI|, \verb|u-95% CI|, \verb|Rhat|,\verb|Bulk_ESS|,\verb|Tail_ESS|とあります。後ろの三つはMCMCがうまくいったかどうかの診断に使われる数字で，今は一旦横に置いておきましょう。大事なのは推定値ですから。
で，\verb|Est.Error|。最尤推定の時はStandard Errorと書かれていましたが，ベイズ推定ではEst.Errorと書かれています。似ているようで違います。最尤推定のStandard Errorは，推定値がどれぐらいの幅でブレるかを表すものでした。ベイズ推定のEst.Errorは，事後分布の標準偏差です。ベイズ推定は，推定値が確率的，事後分布として得られることを思い出してください。この事後分布の標準偏差を計算したものが，Est.Errorであり，「この幅に入ると言って当たる確率が95\%」ではなく，「この幅にある確率が95\%」ということです。

後ろの\verb|l-95% CI|と\verb|u-95% CI|は，それぞれ95\%確信区間の下限(lower)と上限(upper)です。CIは信頼区間Confidence Intervalのそれと区別して\keyterm{確信区間}{かくしんくかん}{credible interval}と呼ばれます。このように，推定の結果の背後についているのが，分布の情報になっているところが，最尤推定とベイズ推定の大きな違いです。

ところで，推定値自体は大きく変わりませんでした。「なんだ，同じ答えなら苦労してベイズにする意味がないじゃないか」と思われたかもしれません。しかしこれは，むしろ安心してよい結果なのです。329人分ものデータがあれば尤度は十分に強い情報を持っていますから，弱い事前分布の影響は相対的に小さくなり，最尤推定とほぼ同じところに落ち着きます\footnote{逆に言えば，データが少ないときには両者は一致しません。そのようなときこそ事前分布の置き方が効いてきますし，何を仮定して推定しているのかが問われることになります。}。ベイズにすると答えが変わる，という話ではないのです。そもそも，方法は違っても推定しようとしている母集団が同じなんですから，手法によって結果が都合のいいように変わるはずもないのです。

変わるのは，\textbf{得られるものの性質}です。\verb|lm()|が返してくれたのは，1組の点推定値とその標準誤差でした。これに対して\verb|brm()|が返してくれたのは，4000組のパラメータの乱数です。ここに決定的な違いがあります。前節で見たように，乱数が大量にあるということは，分布の形そのものが手元にあるということでした。図\ref{fig:29_04}に，得られた事後分布を描いてみました。

\begin{figure}[ht]

	\includegraphics[keepaspectratio,width=0.8\linewidth]{figures/29_bayesian_modeling/posterior_regression.png}
	\caption{brmsで推定したパラメータの事後分布。濃い部分が95\%確信区間を表す}
	\label{fig:29_04}

分布が手元にあると，たとえば「傾きが1.1より大きい確率はどれぐらいか」という問いに，そのまま答えることができます。4000個の乱数のうち1.1を超えているものの割合を数えればよいだけだからです。標準誤差から検定統計量を計算して，$p$値の表を引いて，といった手続きは必要ありません。


\section{stan言語を使ったプログラミング}

brmsは便利ですが，中で何が起きているのかが見えないままでは，やがて行き詰まります。brmsが書けるのは「回帰モデルの形に収まるもの」までで，それを超えるモデルを考えたくなったときには，結局Stanコードを自分で書くことになるからです。

StanのコードはC++言語の書き方をしますから，最初は慣れないかもしれません。Rと違って，古典的で厳格な書き方を必要とする言語です。大きな違いは，次の3つです。

\begin{enumerate}
  \item 一行の終わりをセミコロンで書くこと
  \item 変数の型を宣言してから使うこと
  \item ブロック構造を意識して書くこと
\end{enumerate}

一つ目の点は，単なる表記上のマナーです。英語ではピリオド，日本語では句点で一文の終わりを示すように，C++言語ではセミコロン\verb|;|で一行の終わりを示します。実はRでも複数行を一行にまとめるときにはセミコロンで区切ることができます。たとえば\verb|a <- 1; b <- 2; c <- a + b|のように書くことができるのです。
Rではセミコロンを入れなくても，改行すればそれで一行と見てくれますが，これはインタプリタ言語だからで，改行が入力(Rに対する指示実行)を意味するからですね。C++言語はコンパイル言語ですから，改行は意味を持ちません。セミコロンで一行の終わりを示す必要があるのです。これはもう，慣れてもらうしかありません。

二つ目の\textbf{型宣言}は，変数の性質を宣言してから使うということです。Rでは，オブジェクトに何か代入するとき，\verb|a <- 5|とか\verb|obj <- list(c(1,2,3))|のようにいきなり思いついたオブジェクト名，\verb|a,obj|を使って代入していました。実は，Rは少しやんちゃな言語なんです。C++言語はお上品に，まず「整数のオブジェクト，Nを使わせていただきます。この中には1以上の整数しか入れません」「ベクトルのオブジェクト，muを使わせていただきますので，サイズはNのベクトルを用意してください」，というお伺いを立ててから使うことになります。C++/Stan言語はこのように，使う変数名をブロックの最初に書いて，しっかりと管理してくれるのです\footnote{このような宣言が必要な歴史的経緯として，まだ計算機の性能が貧弱だった頃の時代背景があります。変数でもなんでも，計算機の中では本質的に短期的に記憶するためにメモリを使います。整数の\verb|1|がはいった\verb|a|をメモリに記憶しておくとき，メモリのxxxx番地からxxxxx番地までを\verb|a|の領域として取っておこう，ということが内部で行われます。ここで\verb|a|にはいま1が入っていますが，このあとどんな数字が入るかわかりません。2になったり100になったりするかもしれないので，1ビットだけ取っておけば良いというわけにはいきません。なので，扱える整数の範囲だけ領域を一旦確保しておくことになります。ここで，型が重要になってきます。というのも，整数の場合と実数の場合とでは，確保しておく領域のサイズが変わるからです。実数は小数点以下の値をもちますから，整数部分と小数部分の両方を確保しておく必要があります。メモリが無尽蔵にある今では気にしなくていいですが，昔の貧弱なメモリ空間では実数の領域を確保することと，整数の領域を確保することでは，メモリにかける負担が大きく違っていたのです。なので，メモリを使う前にどれぐらい使うのか教えておいて！(宣言して！)というのはメモリ管理上重要なステップなのです。}。

いちいち書くのは面倒だ，と思われるかもしれません。今まで野放図なRの世界だったので，急にマナーに厳しいこの業界に来ると不自由さを感じるのでしょう。でもこれはこれで，慣れると便利です。おかしな数字になったり，あり得ない値が出てこないようにする，という安全装置の役割も果たしているからです。

たとえば標準偏差パラメータは，負の数になることはありません。二乗して平方根を取った正の値なのですから，負の数が出てくるはずがないのです。Stanで標準偏差パラメータを推定したいとしましょう。推定したいパラメータ，変数も宣言する必要があります。その時，\verb|real<lower=0> sigma;|のように書きます。標準偏差パラメータ\verb|sigma|はreal型(実数値)で，0以上の値しか取らない，と宣言しているのです。もしも負の値が出てきたら，Stanはエラーを返してくれます。Rでは，\verb|sigma <- -1|と書いてしまうと，そのまま-1が入ってしまいます。Stanはそういうことを許さないのです。変数は使う前に宣言する，というのは他の言語でもよくあることですから，慣れてしまえば大したことはありません。

さて，最後の\textbf{ブロック構造}についてです。これは，関数などひとかたまりになるところをブロックとして，中括弧\verb|{}|で囲む，という表記です。C言語では関数，クラス，オブジェクトなど色々なものがブロックになりますが，Stanでは決まったものだけがブロックになります。Stanのブロックは次のとおりです。

\begin{description}
  \item [dataブロック] データを宣言するブロックです。Rなど，Stan外から受け取るデータの型と名前を宣言します。
  \item [transformed dataブロック] データを変換するブロックです。Stan外から受け取ったデータを，Stan内で使いやすい形に変換するためのブロックです。省略しても構いません。
  \item [parametersブロック] 推定したいパラメータを宣言するブロックです。Stanが推定するパラメータの型と名前を宣言します。
  \item [transformed parametersブロック] パラメータを変換するブロックです。Stanが推定したパラメータを，Stan内で使いやすい形に変換するためのブロックです。省略しても構いません。
  \item [modelブロック] データとパラメータの関係を宣言するブロックです。Stanが推定するモデルの形を宣言します。具体的には，尤度と事前分布を書き下すことになります。
  \item [generated quantitiesブロック] 事後分布からの乱数を生成するブロックです。Stanが推定したパラメータを使って，事後分布からの乱数を生成します。省略しても構いません。
\end{description}

必ず必要なのは，\verb|data|ブロック，\verb|parameters|ブロック，\verb|model|ブロックの3つです。その他のブロックは必要に応じて書けば良いでしょう。

以上がStanのコードを書くときの基本的なルールです。でもこれだけで，白紙の状態からStanのコードを書くのはちょっとイメージができませんよね。そこで，RStudioの手助けを借りてみましょう。RStudioのFile > New Fileから，Stan Fileを選んでください。エディタ画面にStanのファイルが開きます。そしてここには既に，サンプルコードが書いてあるのです。これを読んでみましょう。

\begin{Rscreen}{RStudioのStanサンプルファイル。紙幅の関係でコメント文はカットしています。}{out29_02}
	\begin{verbatim}
data {
  int<lower=0> N;
  vector[N] y;
}

parameters {
  real mu;
  real<lower=0> sigma;
}

model {
  y ~ normal(mu, sigma);
}

  \end{verbatim}
\end{Rscreen}

スラッシュが2つ並んでいる\verb|//|はコメント文，この行は無視して良いという意味で，Rでいう\verb|#|と同じですから，無視して構いません。ここに掲載したのはコメント文を除外したものです。

さて，このサンプルコードを見ると，確かに\verb|data|ブロック，\verb|parameters|ブロック，\verb|model|ブロックの3つからなることがわかりますね。
そして，\verb|data|ブロックと\verb|parameters|ブロックでは，変数の型宣言(だけ)がなされています。この変数を使うよ，ということです。コードの中身は次のような意味になります。


\paragraph{コード解説}
\begin{description}
	\item[dataブロック] 整数(integer)型の変数\verb|N|と，長さ\verb|N|のベクトル型の変数\verb|y|を使う，という宣言です。このブロックは外部からデータを受け取るところですから，外部から長さNの実数ベクトルを受け取る，という意味になります。
	\item[parametersブロック] 実数(real)型の変数\verb|mu|と，0以上の実数(real<lower=0>)型の変数\verb|sigma|を使う，という宣言です。このブロックはStanが推定するパラメータを宣言するところですから，Stanは\verb|mu|と\verb|sigma|を推定する，という意味になります。
	\item[modelブロック] \verb|y ~ normal(mu, sigma);|は，\verb|y|は平均\verb|mu|，標準偏差\verb|sigma|の正規分布に従う，という意味です。Stanでは，\verb|~|を使って「従う」という意味を表します。これは尤度関数そのものですね。正規分布からデータが生成されている，とも読めます。
\end{description}

特に\verb|model|ブロックに注目してください。$y \sim N(\mu,\sigma)$というモデルが，ほぼそのまま\verb|y ~ normal(mu, sigma);|と書かれているのがわかると思います。確率分布や尤度関数，$\prod$や$\sum$の記号を使った数式を書かなくていいのです。変数(データ)がどういう確率分布から出てきているかを書けば，モデルが書ける！答えが得られる！これがStanの強みです。ここから先の計算は全部やって，答えを出してくれるというのですから，私たちは確率モデル，データがどういう数式から出てきているかを考えるだけでよくなったわけです。確率プログラミング言語が，数理統計学者だけでなく心理学者のような統計ユーザにも，大きく門戸を開いてくれたということが，少しは実感していただけたでしょうか。

\subsubsection{ちょっと補足}
ここの補足セクションは，読み飛ばして次に進んでもらっても構いません。実践する上で大事なことを2つだけ，書いておきます。
\paragraph{事前分布の記述}
\verb|model|ブロックには尤度と事前分布を書くのですが，ここには事前分布の記述がありません。データ$y$と確率分布の関係，つまり尤度関数しか書かれていないのです。事前分布はどこに行ったのでしょう。

実は，Stanは事前分布を省略することができます。省略した場合は，Stanが自動的に「無情報的事前分布」を設定してくれます。正確には，Stanはパラメータの取りうる範囲を無限大に広げて，その中で一様分布を仮定することになります。つまりどんな値をもとりうる，どういう値になるか全くわかっていない，という状態で推定してくれるわけです。こうしておくと，事後分布の形は尤度をそのまま反映してくれますから，最尤推定とほぼ同じ結果が得られることになります。

もちろん積極的に事前分布を設定することもできます。事前分布はパラメータにおかれるものですから，ここでは$\mu$と$\sigma$に事前分布を設定することになります。たとえば，$\mu$は平均0，標準偏差100の正規分布に従うと仮定したい場合は，\verb|mu ~ normal(0, 100);|と書きます。$\sigma$は正の値しか取らないので，平均0，標準偏差10のコーシー分布に従うと仮定したい場合は，\verb|sigma ~ cauchy(0, 10);|と書きます。

\paragraph{尤度関数を正確に記述する}
もう一度尤度関数を見てみましょう。$y \sim N(\mu,\sigma)$の$y$は，正確にはベクトルですね。要素が$N$個あるベクトルです。数学的に正しく書くならば，

\begin{align}
L(\mu,\sigma|y) = \prod_{i=1}^{N} \frac{1}{\sqrt{2\pi}\sigma} \exp\left(-\frac{(y_i - \mu)^2}{2\sigma^2}\right)
\end{align}

となります。$\prod_{i=1}^{N}$の部分にあるように，データ$y_i$を全部掛け合わせたものが尤度となるはずなのです。ところがStanのコードでは$y$しか書いていない。
正しくは，次のように書くべきです。
\begin{verbatim}
y[1] ~ normal(mu, sigma);
y[2] ~ normal(mu, sigma);
...
y[N] ~ normal(mu, sigma);
\end{verbatim}

つまり，$y$の要素ごとに，平均$\mu$，標準偏差$\sigma$の正規分布に従う，と書くべきです。ただ，Nが5や10ぐらいであればまだしも，大きくなったら大変。ということで，プログラミング言語の表現を借りて，次のようにするのが一般的です。

\begin{verbatim}
for (i in 1:N) {
  y[i] ~ normal(mu, sigma);
}
\end{verbatim}
これで正しく$\prod_{i=1}^{N}$の部分が表現できました。
実際，自分でコードを書くときはこのように\verb|for|文で書くことも多いです。
しかし，同じベクトルに同じ確率関数を適用する場合は，Stanは省略した書き方，すなわちここにある\verb|y ~ normal(mu, sigma);|のような書き方を許してくれます。Stanは，\verb|y|の要素ごとに同じ確率分布に従う，と解釈してくれるのです。便利ですね。

もし尤度関数が，回帰分析のように$y_i \sim N(\beta_0 + \beta_1 x_i, \sigma)$のように，$x_i$の値によって平均が変わる場合は，\verb|for|文で書く必要があります。すなわち，

\begin{verbatim}
for (i in 1:N) {
  y[i] ~ normal(beta_0 + beta_1 * x[i], sigma);
}
\end{verbatim}

としなければなりません。この例のように，$x_i$の値によって毎回尤度関数が変わる場合は，Stanは省略した書き方を許してくれないことに注意してください。

\section{生成量による新しい仮説の立て方}

さて，Stanを使ってコードを書くことができるようになりました。ここから少し発展的な使い方を見てみましょう。

ベイズ推定の利点として追加で説明しておきたいのは，仮説検定的に「手に入ったデータについて考える」のではなく，「データを生み出すメカニズムを考える」という視点が得られるというところです。この視点を特に\keyterm{生成モデル}{せいせいもでる}{generative model}といいます。

たとえば独立サンプルの$t$検定では，これまではA群とB群の数値の列だけが与えられ，さてこの平均値に差があるか，という話から始まりました。その上で，急に複雑な数式が出てきて，そこに数字を当てはめさえすればあとは有意かどうかを判定する数字が出てくる，という感じではなかったでしょうか。こうなると「なんだか分からないけど，$p<0.05$ならいいんでしょ」という理解になってしまいがちなのも無理はありません。このオールドファッションなやり方の利点は，A群・B群の数字がなんであってもいいことです。心理学の実験データでも，農業試験場の農作物のデータでも，経済学でもマーケティングでも法学でも生物学でも，とにかく2群の数列があれば，平均値の差を検定できるという理屈です。やり方が決まっているので，統計ソフトウェアに実装することも簡単ですし，手順を教えるだけで誰にでも使えます。しかしそのことが，誤用・誤解を生んできたのだということを，忘れてはなりません。

しかし，ベイズ的に考えると，A群とB群のデータが独立した正規分布から出てきている，という生成メカニズムの観点から考えます。A群のデータは平均$\mu_A$，分散$\sigma^2$の正規分布から出てきている，B群のデータは平均$\mu_B$，分散$\sigma^2$の正規分布から出てきている，というモデルを考えているのです。ここで確率分布関数・尤度関数はデータを生成するメカニズムだといえます。このような背景を考えるのですから，間違って割合のデータに$t$検定を適用するとか，反応時間のように正規分布しないデータに$t$検定を適用するとか，そういう誤用は起こりにくくなります。なぜなら，そのようなデータはそもそも正規分布から生成されているとは考えにくいからです。生成メカニズムを考えることは，データの性質を考えることにつながります。データの性質を考えることは，適切な分析方法を選ぶことにつながります。ベイズ的な考え方は，このように分析方法の選択にも良い影響を与える可能性があります。

また，MCMC法ではこの$\mu_A,\mu_B,\sigma$といったパラメータを推定するために，乱数を発生させるのでした。乱数とは事後分布を代表する数字であり，データから得られた情報をもとにパラメータが取りうる値の具体的な値をたくさん作っていることになります。乱数を100,000個作るというときは，$\mu_A^{(1)},\mu_B^{(1)},\sigma^{2(1)}$，$\mu_A^{(2)},\mu_B^{(2)},\sigma^{2(2)}$，...，$\mu_A^{(100000)},\mu_B^{(100000)},\sigma^{2(100000)}$というように，100,000組のパラメータの組み合わせを作っていることになります。

さて，このそれぞれの代表値を使って応用的に考えてみましょう。ここで興味があるのは$\mu_A$と$\mu_B$の差です。これを$\delta = \mu_A - \mu_B$という新しいパラメータ$\delta$で表しましょう。これはMCMC法で得られた乱数を使って具体的に計算できて，$\delta^{(1)} = \mu_A^{(1)} - \mu_B^{(1)}$，$\delta^{(2)} = \mu_A^{(2)} - \mu_B^{(2)}$，...，$\delta^{(100000)} = \mu_A^{(100000)} - \mu_B^{(100000)}$というように，差の乱数を100,000個作ることができます。この差の乱数をヒストグラムにすれば，「差」の事後分布が得られます。この差の事後分布を使って，差が0より大きい確率はどれぐらいあるか，差が0より小さい確率はどれぐらいあるか，ということもわかりますし，差の95\%確信区間もわかります。これとROPEを組み合わせれば，差が実質的に意味があるのかどうかの判断ができます。

このようにパラメータから作られる量のことを，\keyterm{生成量}{せいせいりょう}{generated quantities}と呼びます。生成量は，もとのパラメータから計算される新しい量です。ベイズ推定のMCMC法では，この生成量を簡単に計算できるという利点があります。パラメータの事後分布が得られれば，そこから生成量を計算することは容易だからです。差の大きさそのものを考えているわけですから，これが効果量です。わざわざ効果量を別途計算しなくても，生成量として差の大きさを直接考えることができるわけです。さらに差の確率分布を考えているのですから，「差の95\%HDIがゼロを含むかどうか」といった一点についてだけ考えるのではなく，「差が0より大きくなる確率はどれぐらいか」とか，「差が5より大きくなる確率はどれぐらいか」といった具体的な議論ができるようになります。

もっと面白いことも言えますよ。データ生成のメカニズムを考えているわけですから，推定された値を使って，新しくデータを作り出すこともできるのです。A群のデータは平均$\mu_A$，分散$\sigma^2$の正規分布から出てきている，と考えるのでしたね。であれば，\verb|rnorm(100,mu_A, sigma)|とすれば，この$\mu_A,\sigma$の組み合わせから100個の新しいデータを作り出すことができますよね。もちろん同様にB群のデータを作ることもできます。MCMC法では，$\mu_A^{(1)},\sigma^{(1)}$，$\mu_A^{(2)},\sigma^{(2)}$，...，$\mu_A^{(100000)},\sigma^{(100000)}$というように，100,000組のパラメータの組み合わせを作っているわけですから，これらを使って\verb|rnorm(n, |$\mu_A^{(i)}$\verb|, |$\sigma^{(i)}$\verb|)|というように100,000回新しいデータを作り出すことができます。

このように，推定された値を使って作られる予測分布のことを，\keyterm{事後予測分布}{じごよそくぶんぷ}{posterior predictive distribution}と呼びます。事後予測分布が表しているのは，「パラメータがある値だったときに取りうる実現値」のことです。つまり，母集団における母数(パラメータ)ではなく，得られる標本(データ)についての分布を考えることができます。そうすると，どういうことが考えられるでしょうか。これまではA群とB群の母平均に差があるかどうか，という話をしていましたが，「もし新しくデータを取ったときに，A群の人がB群の人よりもスコアが高い確率は」といったことがわかるようになりますよね。これを仮説として検証することも，もちろん可能です。

世の中には「男性脳と女性脳」「日本人と外国人」のように，大きな主語で物事が語られることがあります。しかしそれらは，平均的には差があるという話であって，平均を中心とした分散をともなって一人一人のデータとして実現するわけですから，あまり意味のないことも少なくありません。一言で言うと効果量が小さい場合が多いのです。たとえば「男性は女性よりもたくさん食べる」ということが統計的に示されたとしても，少食の男性もいるし，たくさん食べる女性もいるでしょう。もしあなたが次に初めて出会う男性が女性よりたくさん食べるかどうかを知りたければ，平均値の差があるかどうかを調べるよりも，事後予測分布を使って「男性が女性よりたくさん食べる確率はどれぐらいか」を調べた方がよほど実践的です。このように，生成モデルの視点からデータを考えることは，仮説の立て方や検証の仕方にも新しい可能性をもたらします。

新しく得られるデータにおいて，一方の群が他方の群よりどれほど大きいか，という指標を\keyterm{優越率}{ゆうえつりつ}{probability of dominance}と呼びます。また，両方の群がどれほど重複しているかを表す指標として，\keyterm{被覆率}{ひふくりつ}{overlap coefficient}というものもあります。実はこれらの指標は，ベイズ統計学による生成量のアプローチを待つまでもなく，頻度主義統計学の中でも提案されてきた指標です。ですが，頻度主義的統計学の誤用・誤解の広がりのように，$p$値万能主義の中でこれらの指標にはあまり注目されてきませんでした。ベイズ的アプローチ，特にMCMCを使った生成量のアプローチで，これらの指標が簡単に計算できるようになったことで，改めて注目されるようになってきています。皆さんもぜひ柔軟な姿勢で，分かりやすい角度から仮説を考えるようにしてください。

\section{補遺・Stan環境の準備}
\label{prepare_stan}
\subsection{インタプリタ言語とコンパイラ言語}
パッケージ\verb|brms|はRのパッケージですが，その中でStanを使います。
ですから，CRANから\verb|brms|をインストールするだけでなく，それとは別にStanの環境を整えなければなりません。

StanはR/RStudioのように，ダウンロードしてきたらコンソールが出てきて，そこに書き込んで実行するというような使い方はしません。インストールしても決して表に出てくることなく，PCの中に潜んで事後乱数の計算をしてくれるものです。表に出てこないし，アイコンも出てこないので，インストールしたことが分かりにくいところがあります。
ちなみにRのように一問一答型で実行できるのはインタプリタ言語といい，Stanのように表には出てこず結果だけ返すような言語をコンパイラ言語と言います。Stan言語でかかれた事後分布からの乱数発生装置・指示書を機械の言葉に翻訳(コンパイル)して，みなさんのPCが直接わかる機械の言葉で計算させます。インタプリタ言語は逐一の翻訳が必要なので計算スピードが遅い\footnote{といっても，みなさんが使っている分には十分早く，瞬時に答えが返ってくると思いますが。}のに対し，コンパイラ言語は一度設計図全体を完全に翻訳させてから計算させるので，翻訳に少し時間がかかるけれども，翻訳後のスピードはものすごく速いのです\footnote{といっても，Stanで計算させる内容はモデルが複雑になれば，さすがにみなさんのPCでも数分から数十分かかることもあるでしょう。私なんかは込み入ったプログラムを書きすぎて，数時間から数日計算し続けるなんてこともあります。}

さて，この翻訳にはC++という言語が使われています。C++も言語，Stanも言語，Rも言語なんですが，C++は非常に古典的かつ汎用的な言語で，Stanの翻訳に使われるだけでなく，ゲームやアプリケーションの開発にも使われています。たとえばWindowsやMacのOSなんかも(以前は)C++で書かれていました。StanはこのC++の翻訳機能をいわば利用させてもらう言語なので，みなさんのPCにはC++のコンパイラ(翻訳機)を入れ，さらにStanを入れる，という手順が必要です。

初学者にとって，Stan言語の壁があるとすると，この導入の箇所，環境構築なのです。
計算機を使う上で，ファイルの場所，ディレクトリ構造などの基本的な知識が必要で，失敗すると「Stanが動かない」ということになってしまいます。RやRStudioのように，アイコンをクリックしたらインストールできて，アイコンをクリックしたら起動する，というような簡単な関係にないところが難しいところです。しかも，RやStanはもちろん，OSも日々アップデートしますよね。となると，人によって環境・OSの微妙な違いがあちこちにできます。しかもこのテキストのように，「こうやってインストールしますよ」という説明が日々時代遅れになってしまう。これは文章書きとしては致命的な問題で，ほとほと困ってしまいます。


さて。泣き言を言っても仕方がないので解説していきますが，前提として次のことを約束してください。
\begin{itemize}
    \item 自分の今の環境(PC, OS)を把握し，OSはアップデートを当てた最新のものにしておくこと。
    \item RやRStudio環境についても同じ。アップデートをして，常に最新のものにしておくこと。新しいバージョンは，前のバージョンの不具合を修正してくれているのです。なんだか面倒だから，よくわからないから放置する，というのがトラブルの元になります。
    \item ここで説明するのは書いてる時点\footnote{2026年8月18日現在}での情報です。時間が経つごとにこの情報は古くなりますので，Stanの公式サイトやRの公式サイトで最新情報を確認してください。
\end{itemize}

既にRやRStudioを使っている，あるいは以前Stanを入れたはずだけど時間が経っているひとは，まずはRやRStudioを最新のものにアップデートしてから始めてくださいね。

\subsection{Stan環境の準備}
ここからは，OSごとにやり方が異なりますので，みなさんは必要なところを読んでください。ちなみにこのステップは，Stanの公式サイト\url{https://mc-stan.org/install/}に書かれています。最新版も確認してください。
\subsubsection{MacOSの場合}
\begin{enumerate}
    \item まずC++環境ですが，これはXcodeというApple純正の開発環境を入れるのが簡単です。App StoreからXcodeをインストールしてください。これでC++環境が入ります。
    \item Rを起動して，コンソールで次のように入力します。これでStanのRパッケージが入ります。まずRパッケージを入れるのです。
\begin{quote}
\texttt{install.packages("cmdstanr",}\\
\texttt{\ \ repos = c("https://stan-dev.r-universe.dev",}\\
\texttt{\ \ \ \ \ \ \ \ \ \ \ \ \ \ getOption("repos")))}
\end{quote}

    \item パッケージが入れば，それを使ってStanを入れます。コンソールで\verb|cmdstanr::install_cmdstan()|と入力してください。
\end{enumerate}
\subsubsection{Windowsの場合}
\begin{enumerate}
    \item まずC++環境です。公式サイトにはCondaを使えばいいのでは，ともありますが，それよりも簡単なのはRtoolsを入れることです。RtoolsはRの公式サイトからダウンロードできます。\verb|CRAN R|と検索して，\url{https://cran.r-project.org/}に行きます。ここでbaseを選ぶとR本体が入りますが，その下にある\verb|Rtools|を選んでインストーラをダウンロードします。ちなみにこのRtoolsは，Rのバージョンに合わせたものを選ぶ必要があります。2026年8月18日現在の最新Rは4.6.1で，RtoolsはRtools4.5が最新です\footnote{Rのバージョンが4.6.1なのですから，Rtoolsも4.6であって欲しいのですが，まだ提供されていません。が，4.5が4.6.1でも動きますので，それで。}。
    \item インストーラがダウンロードできたら，それをダブルクリックします。インストールときに「PATHに追加する」オプションをクリックして選択してください。また，インストール先にも注意してください。自分のドキュメントやProgram Filesの中に入れると，OneDriveという仮想空間の中に入ってしまい，PCにその実体が入らないという不具合が生じかねません。おすすめはCドライブ直下。Cドライブに\verb|Rtools|というフォルダを作って，そこに入れるのが無難です。いずれにせよ，\textbf{どこにインストールしたかをしっかり把握しておいてください。}
    \item この後はMacOSと同じです。Rを起動して，コンソールで次のように入力します。これでStanのRパッケージが入ります。まずRパッケージを入れるのです。
\begin{quote}
\texttt{install.packages("cmdstanr",}\\
\texttt{\ \ repos = c("https://stan-dev.r-universe.dev",}\\
\texttt{\ \ \ \ \ \ \ \ \ \ \ \ \ \ getOption("repos")))}
\end{quote}

    \item パッケージが入れば，それを使ってStanを入れます。コンソールで\verb|cmdstanr::install_cmdstan()|と入力してください。
\end{enumerate}

インストールが終わったら，最後にRに「どこにStanが入っているか」を教えてあげる必要があります。
インストールの最後に「このパスにインストールしたよ」という情報が表示されているはずです。そのパスをコピーして，Rのコンソールで\verb|cmdstanr::set_cmdstan_path()|の\verb|()|の中に貼り付けてください。これでRがStanの場所を認識します。

うまくインストールできたかどうか，確認するためにCmdStanRのサイト，\url{https://mc-stan.org/cmdstanr/articles/cmdstanr.html}をみてみましょう(「Getting started with CmdStanR
」で検索するといいでしょう)。
そこには上でも述べたインストールの方法が書いてありますが，その下にサンプルコードがあります。

\begin{lstlisting}[language=c++,label={code:29_07},caption={Stanサンプルコード}]
file <- file.path(cmdstan_path(), "examples", "bernoulli", "bernoulli.stan")
mod <- cmdstan_model(file)
\end{lstlisting}

このコードが走れば，あなたのPCにはStanが入っていることになります。もしエラーが出る場合は，どこかで手順を間違えている可能性があります。バージョンを確認する，パスを確認することが大事です。
エラーが出たら，私や生成AIに相談してください。でも「なんかうまくいかない！」ではなく，自分の言葉で自分の環境について説明し，このバージョン，このパスで，このエラーが出る，というような伝え方をしてくださいね。助ける側もノーヒントでは助けられません。自分の環境を把握することが，Stanを使いこなす第一歩です。
